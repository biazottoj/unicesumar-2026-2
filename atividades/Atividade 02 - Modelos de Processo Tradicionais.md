# Atividade PBL — Aplicação de Processos e Prototipação ao Projeto

## Objetivo

Aplicar os conceitos de **processo de software**, **atividades fundamentais**, **modelo cascata** e **modelo de prototipação** ao projeto PBL que o grupo vem desenvolvendo.

## Organização

- Atividade em grupos;
- Não é necessário utilizar internet;
- Toda a atividade deverá ser produzida por escrito;
- Cada grupo deverá entregar um único documento.

---

# Etapa 1 — Retomada do projeto

Registrem:

- nome provisório do projeto;
- problema que o projeto pretende resolver;
- público-alvo;
- objetivo principal do produto.

---

# Etapa 2 — Aplicação do processo de software

## 1. Elementos do processo

Para o projeto do grupo, identifiquem:

- **Insumos:** informações necessárias para iniciar o trabalho;
- **Atividades:** ações que deverão ser realizadas;
- **Papéis:** pessoas envolvidas ou responsáveis;
- **Resultados:** documentos, modelos ou protótipos que deverão ser produzidos.

## 2. Atividades fundamentais

Expliquem como cada atividade aparece no projeto:

- **Especificação:** o que precisa ser descoberto e definido;
- **Projeto:** como a solução será representada;
- **Validação:** como o grupo verificará se a proposta atende aos usuários;
- **Evolução:** como mudanças poderão ser incorporadas posteriormente.

> Considere que o projeto será desenvolvido por meio de documentos, modelos e protótipos, sem programação.

---

# Etapa 3 — Requisitos e dúvidas do projeto

## 3. Requisitos já conhecidos

Listem pelo menos **cinco necessidades ou funcionalidades** que já estão claras.

## 4. Aspectos que ainda precisam ser esclarecidos

Elaborem pelo menos **cinco perguntas** que deveriam ser feitas aos possíveis usuários ou interessados.

As perguntas devem ajudar a esclarecer:

- informações de entrada;
- resultados esperados;
- regras de funcionamento;
- limitações;
- necessidades dos usuários.

---

# Etapa 5 — Primeiro ciclo de prototipação

## 5. Planejamento do ciclo

Descrevam brevemente como o grupo realizaria cada etapa:

1. Obter requisitos;
2. Elaborar um projeto rápido;
3. Construir o protótipo;
4. Avaliar o protótipo;
5. Refinar o protótipo.

## 6. Protótipo de baixa fidelidade

Desenhem, em papel, pelo menos **três telas ou representações principais** do produto.

O protótipo deve apresentar:

- títulos;
- campos de entrada;
- botões ou ações;
- informações exibidas;
- ligação ou navegação entre as telas.

Não é necessário produzir um desenho artístico. O objetivo é representar o funcionamento da solução.

---

# Etapa 7 — Avaliação rápida

Troquem o protótipo com outro grupo.

O grupo avaliador deverá registrar:

- uma parte que ficou clara;
- uma dúvida sobre o funcionamento;
- uma informação que parece estar faltando;
- uma sugestão de melhoria.

Após receber o feedback, o grupo deverá anotar pelo menos **duas alterações** que faria no protótipo ou nos requisitos.

---

# Entregável

Cada grupo deverá entregar:

1. resumo do projeto;
2. identificação dos elementos do processo;
3. aplicação das atividades fundamentais;
4. lista de requisitos conhecidos;
5. perguntas que ainda precisam ser respondidas;
6. planejamento do primeiro ciclo de prototipação;
7. protótipo com pelo menos três telas;
8. feedback recebido;
9. alterações propostas após a avaliação.
