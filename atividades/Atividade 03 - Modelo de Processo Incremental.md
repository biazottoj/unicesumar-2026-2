# Evoluindo o Produto por Incrementos

## Objetivo

Planejar como o produto do projeto PBL pode ser construído progressivamente, priorizando primeiro aquilo que entrega maior valor ao usuário.

**Tempo estimado:** 50 minutos  
**Organização:** grupos do projeto PBL  

---

# 1. Retomando o Produto

Registrem:

- problema que o projeto pretende resolver;
- principais usuários;
- objetivo do produto;
- pensem e registrem entre **5 e 8 funcionalidades** já imaginadas para o sistema.

---

# 2. Identificando o Núcleo do Produto

Respondam:

> **Se vocês pudessem entregar apenas uma pequena parte desse produto, o que precisaria existir para que ele já tivesse alguma utilidade para o usuário?**

Escolham apenas **2 ou 3 funcionalidades essenciais** para formar o **Incremento 1**.

Para cada funcionalidade escolhida, expliquem:

- por que ela é essencial;
- qual problema ela ajuda a resolver;
- quem poderia utilizar essa primeira versão do produto.

---

# 3. Planejando os Próximos Incrementos

Distribuam as demais funcionalidades entre três incrementos:

- **Incremento 1 — Núcleo:** menor versão do produto que já entrega valor;
- **Incremento 2 — Ampliação:** adiciona funcionalidades importantes;
- **Incremento 3 — Refinamento:** adiciona melhorias e funcionalidades menos prioritárias.

Preencham a tabela:

| Incremento | Funcionalidades | Valor entregue ao usuário |
|---|---|---|
| Incremento 1 |  |  |
| Incremento 2 |  |  |
| Incremento 3 |  |  |

---

# 4. Simulação de Feedback

Troquem os projetos com um grupo. O que está avaliaando deve analzar o planejamento e dar feedback. O grupo que avalia responde:

- qual funcionalidade seria antecipada;
- qual funcionalidade poderia ser adiada;
- se algum incremento precisaria ser reorganizado;
- por que essas mudanças seriam realizadas.

---

# 5. Representação da Evolução do Produto — 10 minutos

Registrem uma representação uma nova versão dos incrementos, mostrando como o produto evoluirá.

---

# 6. Reflexão Final

Respondam:

1. Por que o grupo escolheu essas funcionalidades para o primeiro incremento?
2. O que poderia acontecer se todas as funcionalidades fossem planejadas para uma única entrega?
3. Como o feedback entre os incrementos pode alterar o produto final?
